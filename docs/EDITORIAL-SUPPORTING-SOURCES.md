# Trusted prerequisite evidence

Reference explanations can now teach prerequisites from complete, independently reviewed supporting manual procedures. This addresses real gaps such as a battery-tray page referring to battery removal, which in turn refers to battery disconnection.

Supporting records must identify exact current source hashes, complete source-unit and illustration counts, and a direct reachable relationship from the primary article. Disconnected, cyclic, stale, incompatible-engine or incompletely reviewed records are rejected. Production resolves the documents from its own catalog; it does not trust source text supplied by an overlay. Supporting facts can extend explanatory text, introductions and requirements. Original action-text and title numeric checks remain tied to their original evidence.

A supported overlay is checked against dependency hashes on every lookup, so an old cache result cannot hide a changed prerequisite. Existing overlays without supporting records keep their prior behavior. This is source verification and independent Codex review, not human mechanical certification.

Validation: 303 tests pass, including nested dependency relationships, stale-source rejection, coverage mismatches, action/title numeric isolation and cache invalidation. The application build passes. Production activation and immutable runtime provenance are recorded after deployment.
